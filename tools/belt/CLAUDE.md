# belt, Claude Code guard, hint and ledger hooks

Go CLI. Central hook binary for Claude Code sessions, with four concepts: **guards** inspect a tool call before it runs and deny risky ones with a reason the model reads. **Allows** run after every guard passed and may answer allow for one narrow, read-only call shape; each is off until the config turns it on. **Hints** inspect a tool call after it ran and add advisory context the model reads next to the result. **Ledger** entries record session lifecycle events (subagents, tasks, permission denials, notifications, compaction, session end, turns that died on an API error) to the events service and reach no model. One opt-in helper sits on the ledger's service: `belt watch` wakes an idle session when an item addressed to it arrives. Pairs with `suspenders` (the git-hook layer): suspenders guards commits, belt guards the session before anything reaches git.

The split is load-bearing (docs/adr/0008, docs/adr/0024, docs/adr/0032). A guard exists to prevent damage that is hard to undo. An allow exists to skip a prompt for a call that is provably a read; it has no denial path and runs only when no guard denied, so a deny always wins. A hint exists to improve a choice that was merely suboptimal, and a ledger entry exists to leave a record. A hint has no denial path in its interface, so it cannot block a tool call even by mistake. The record entrypoint has no output writer, so it cannot steer a session even by mistake. `belt watch` is the one command that exits 2, on purpose: that is the asyncRewake wake signal.

Born out of a July 2026 session retrospective: a session pushed straight to master and tried to self-merge, and internal names reached `git commit` twice before the pre-commit hook caught them. belt moves both checks to the earliest point a hook can intervene.

## How it works

`internal/hook` parses a PreToolUse payload from stdin, runs the guards registered for that event, and writes a deny decision to stdout. A payload it cannot read denies with `belt[payload]:` before any guard runs, like a broken config; `operating.md` (failure modes) states that rule in full. Deny always travels in `hookSpecificOutput.permissionDecision` with exit 0: a hook must not break tool calls on its own bugs, so the deny is data, not a process exit code. Guards for an event run in registration order and the first denial wins; every deny reason is prefixed `belt[<guard-id>]:` so a block is always attributable to the guard that fired. Only when `guard.RunClean` reports a clean pass (no denial, and no guard that failed open or warned in soft mode, seen through each guard's `emit`) does the hook run the enabled allows (`guard.Approve`); the first approval becomes `permissionDecision: "allow"` with a `belt[<allow-id>]:` reason, and an approval posts no event.

`internal/config` treats `~/.config/belt/config.yaml` as the belt-owned surface: per-guard toggles, exclude paths, extra patterns, `claude_settings`, and the `internal_names` section. That section may list shared names files under `include` (docs/adr/0016). Those files are belt-named surfaces read strictly, `blocked_words`/`allowlist`/`allow_phrases` only, and are appended to the section's own lists. `$XDG_CONFIG_HOME` moves the directory; `--config`/`$BELT_CONFIG` relocate the file itself. A legacy `config.toml` beside the default file is read only when the YAML file is absent. A present-but-broken file of either format never falls back to the other one.

The config is standalone and has no machine-profile concept (docs/adr/0010). belt never reads another tool's file, and an absent `internal_names` section means an empty name set. The provisioning layer renders one config per machine class. A guard or rule meant for only some machines is simply absent (or disabled) in the other classes' files. Exactly one non-belt surface is read: `~/.claude/settings.json` + `settings.local.json`, gated by `claude_settings.enabled` (default true). The hooks read their `permissions.deny` Bash entries live for the script guard (shared source of truth with the permission system). `belt doctor` also reads their `hooks.PostToolUse` entries, only to check the `belt hint read` matcher.

A missing config file yields the armed defaults with no error. A config file that is present and fails to parse or validate is an error `config.Load` returns. So is a names file listed under `internal_names.include` that is missing or broken. `belt hook` turns either into a `belt[config]:` deny on every tool call. belt cannot distinguish "no rules" from "the rules did not load", so it blocks rather than run unarmed (`doctor` and `config` still print, flagging that the state shown is the defaults). Validation covers the keys that parse and then do nothing:

- a `custom_guards.<name>.event` outside `bash`/`write`;
- a `custom_hints.<name>` entry whose event is not `session-start` or `subagent-start`, whose command is empty, or whose name shadows a built-in hint;
- a `custom_hints.<name>.agent_types` key on a hint not on `subagent-start`, or one that is empty or holds a blank entry or one with a `*` before its end;
- `mode:` values that are neither `hard` nor `soft` or that sit on a guard outside `config.SoftModeGuards`.

The `ledger`, `watch` and `allows` sections (`internal/config/lifecycle.go`, `internal/config/allows.go`) are deliberately outside validation: a config error denies every guarded call, far too much for a typo in an optional feature. Their accessors clamp (poll floor 100 ms, max wait cap 1 h, negative means default) and rewrite sources the way the events service sanitizes them. `Adjustments()` names each change, and `belt doctor` warns with it. Only YAML type errors still fail the file. Keep it that way when adding a key to either section.

`ledger.agent_types` (`internal/config/agenttypes.go`) goes one step further: its own `UnmarshalYAML`/`UnmarshalTOML` decode any shape. A wrong type, a duplicate key, a `*` before a key's end, an effort outside low/medium/high/xhigh/max, or an empty model drops that entry or tag with an adjustment. So even a type error there cannot fail the file. `UnmarshalYAML` walks the mapping pair by pair on purpose: yaml.v3 fails a whole decode on one duplicate key, which would cost every valid entry beside it.

Rollout order: a binary older than a newly accepted config value (subagent-start, for one) rejects it and denies everything. So the fleet must `ralph up` the new belt before a machine config uses the value. A new key fails the other way, because the YAML decode drops unknown keys. An older belt ignores a custom hint's `agent_types` and runs the hint for every subagent. It also ignores `ledger.agent_types` and records no model or effort. A belt that knows `agent_types` but not `*` matching reads a `*` entry literally, so a gated brief reaches no subagent until the new belt is installed. The same order applies.

Every hook payload's identity reaches the checks: `session_id` always, `agent_id`/`agent_type` inside a subagent. They are copied into `guard.Input` and `hint.Input`, added to custom guard and custom hint stdin only when set (`guard.Identity.AddTo`), and tag every deny and hint event. The session and agent fields are `lenientString`: `belt hook` denies a payload it cannot decode (`belt[payload]`), so a field no guard reads must never fail that decode. The lifecycle-only fields live in `recordPayload` for the same reason. The fields the guards do read stay strictly typed: `tool_name`, `tool_input`, `cwd`, and the `tool_input` keys `guardInputFields` lists per event (`hintInputFields` is the hint twin). When `toInput` starts reading a new key, add it there, or a mistyped value reaches the guards as `""`.

### Guards

| id | event | rule |
|----|-------|------|
| `git-push-main` | `bash` | Deny `git push` targeting main/master unless the target repo is on the shared `direct_main_repos` list or the guard's `allow_repos` allowlist (`pushExempt`; both canonical `host/owner/repo`, e.g. `github.com/mad01/dotfiles`, or a trailing `/*` org wildcard, resolved from the push working dir's `origin` remote). Unresolved repos and off-allowlist repos fail closed; a machine class where direct pushes are fine disables the guard in its rendered config. Resolves bare `git push`/`HEAD` refspecs via `git rev-parse --abbrev-ref HEAD` in the payload cwd (or the `git -C` dir). Tracks `cd`/`pushd` across the command's segments, expanding a leading `~`, `$HOME`, or `${HOME}` in a cd target and a `git -C` target alike, and sending a bare `cd` home. A variable the command sets to a plain literal path (`S=~/repo; git -C $S push`, `${S}` and `"$S"` too) is substituted first (`resolveLiteralVars` in `gitutil.go`, shared by every `walkSegments` caller). That happens only when nothing could leave it empty or change it before the use. The name gets one assignment, at the start or after a `;` or newline, with no quote before it. The command must also hold no heredoc, subshell, brace group, comment, backslash, glob, keyword, other variable, zsh modifier like `$S:h`, or builtin such as `eval`, `read` or `source`; otherwise every variable stays as written. A cd or `-C` target only a shell can resolve leaves the directory unknown, as do `popd`, a bare `pushd`, `cd -P`, and `--git-dir`/`--work-tree`, and a default-branch push from an unknown directory is denied with a hint. A cd the shell may not run as written is unknown too: `cd +1`, `chdir`, any word before cd but `builtin`, a cd after `||` or in a pipeline, or a relative target while CDPATH is set. So is git with `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR` or `env -C`, and a push where git reads no branch, as after a failed cd and `;`. A `-C` path is handed to git as written, since git resolves `..` physically where a shell's cd is logical. git never runs in belt's own process cwd to fill the gap. |
| `git-discard` | `bash` | Deny git commands that throw away uncommitted work: `git stash` (bare, flag-led, `push`, `save`; `list`/`show`/`apply`/`pop`/`branch` allowed), `reset --hard`, a path checkout (`checkout -- <path>`, `checkout <ref> -- <path>`, `checkout .`) or a forced one, `switch --discard-changes`/`-f`, `restore` unless only `--staged` is given, and `clean` with `-f` (not `-n`). Each invocation is judged where it runs (tracked `cd`/`pushd`, `git -C`, else the session cwd, via `walkSegments`). A clean tree (`git status --porcelain` empty, plus `--ignored` for `clean -x`/`-X`) allows, since nothing is lost. An unresolvable directory or a failing `git status` denies. The reason tells the model to run it only when the user's latest message asked for it, and otherwise to ask or hand the user `! <command>`. `allow_repos` exempts repos by canonical identity; `mode: soft` warns via events instead. Born from a session audit that found agents stashing, hard-resetting, and checking out over the user's work unasked. |
| `git-identity` | `bash` | Deny `git commit` when the repo's effective `git config user.email` does not match the first `git_identity` rule covering the repo. The repo is the one the commit runs in: a tracked `cd`/`pushd`, a `git -C` target (`~` and `$HOME` expanded), else the session cwd; a directory only a shell can name fails open. Rules are repo-pattern scoped (exact `host/owner/repo` or trailing `/*` org wildcard) rather than profile scoped. The repo decides the expected identity whatever machine the commit happens on. So a work machine committing to a personal repo in the evening still gets the personal email enforced. `mode: soft` downgrades the deny to a warn event. No config, an unresolved repo or email, and uncovered repos all fail open. |
| `commit-guard` | `bash` | The work-hours nudge: `git commit` to repos matching a `commit_guards` rule inside its local-time window (`block_hours`, `block_days` defaulting to mon–fri) is denied (`mode: hard`) or warned about via the events service (`mode: soft`, the default). A rule meant for one machine class lives in that class's rendered config. `always_allow` exempts repos needed at any hour. A rule's `override` names a timed switch (`belt override set <name> --reason "..."`, 10m default, `--for` to size, `extend` to push). Set and extend require a non-blank `--reason` archived to the events service. The switch suppresses the rule with a warn event until it expires or is cleared. The repo is resolved where the commit runs (a tracked `cd`, a `git -C` target, else the session cwd), as for git-identity. Unresolved repos and malformed windows fail open. |
| `script-deny-list` | `bash` | Deep deny inspection: apply the Bash deny list inside scripts, closing the "write it to a script, then run the script" bypass. Scans executed/sourced script files (`bash x.sh`, `python x.py` incl. versioned names, `perl`/`ruby`/`node`/`osascript`, `uv run`, `./x.sh`, extensionless `./x` with a shebang, `source x.sh`, relative paths resolved against the payload cwd). Also scans `-c`/`-e` strings, heredocs, `bash < x.sh` stdin redirects, `cat x.sh \| bash` pipes, a heredoc or here-string passed through `cat`/`head`/`tail`/`tee` into an interpreter (`cat <<EOF \| sh`), and the command after the indirection heads `eval`, `xargs`, and `find -exec`. A file written and run in one command (`echo '…' > s.sh && bash s.sh`, `tee` too) gets the raw command text scanned — at check time the file doesn't exist yet. So does a written file the command gives an execute bit (`chmod +x s.sh`, `chmod 755 s.sh`). A mode that adds none (`600`, `-x`) is left alone. `curl\|wget` piped into an interpreter denies outright: nothing can read what would run. Patterns = `permissions.deny` `Bash(...)` entries read live from `~/.claude/settings.json` + `settings.local.json` (read gated by `claude_settings.enabled`, default true), plus `extra_patterns` in the belt config (carries `rm -rf`/`rm -fr`, since settings only lists `rm` under "ask"). A `re:` prefix compiles the rest as a case-insensitive regex for flag-reordering shapes. Matching is per non-comment logical line (backslash continuations joined), whole-word, whitespace-normalized, with a second pass that collapses quotes/commas/brackets so `kubectl "delete"` and list-form `subprocess.run(["rm", "-rf", …])` match too. One shape is read as code instead (`scriptpy.go`): a Python heredoc that is the whole command (after optional `cd DIR &&` steps) and runs as `python3 -I` by bare name (a path like `./python3` may link to a shell, so it keeps the text match), with only flags and output redirects on its line and nothing after its terminator. Its body must be quoted or expansion-free, import only json/re/pathlib/textwrap/datetime/collections, and hold no blocked word anywhere, strings included (os, sys, subprocess, posix, builtins, exec, eval, getattr, vars, `_`-prefixed names, frame attributes like `f_globals`, bare `compile`). `-I` is required because Python otherwise imports from the working directory, so a script could write a module and run it. `-I` closes the working directory and the user site directory only: where the user owns the stdlib or site-packages directory (mise, Homebrew), a script can still write a module there and import it, a write the text match never stopped either. Every other interpreter and shape keeps the whole-text match, and a denied Python heredoc's reason names the passing shape. A text heredoc (`scripttext.go`) gets no line checks on its body, since the shell runs none of it. The heredoc must be a bare `cat` or `tee` (optionally after `sudo`), on a line reached through plain lines only (no quotes, comments, substitutions or continuations before it). The targets are an allow-list. Each is a literal path (no variable, glob or `~user`) with a document extension: `.md`, `.markdown`, `.txt`, `.rst`, `.adoc`, `.log`, `.csv` or `.tsv`. JSON, YAML and TOML are left out, because hook runners and mise run commands from `package.json`, `lefthook.yml` and `mise.toml`. No part of the path below the cwd or home may start with a dot, so `.git/`, `.husky/`, `.claude/` and dotfiles are out. The target may not sit under `/etc`, `/private`, `/Library`, `~/Library`, `/usr`, `/opt`, `/System`, `/bin`, `/sbin` or `/dev`, and no directory on the way may be a symlink. A temp folder (`/tmp`, `/private/tmp`, `/var/tmp`, `/private/var/tmp` or `~/.tmp`, but not `$TMPDIR` or `/var/folders`) is a base like the cwd and home, so only the part below it is checked. An existing target must be a regular file with one link and no execute bit. An unquoted delimiter needs a body without `$`, backtick or backslash, and the body may not start with a shebang. Every `cd` must be `cd PATH` followed by `&&`. A relative target counts only after the cds in its own `&&` chain, since a failed cd skips the rest of that chain. `CDPATH` in the command ends the relaxation, and one in the environment makes a relative `cd` unknown. Every other step must be `mkdir`, `touch`, `ls`, `echo`, `printf`, `cat`, `wc`, `pwd`, `true`, `git add\|commit\|status\|diff\|log\|show` without `--output` or `--chmod`, `gh pr\|issue create\|edit\|comment` or `gh release\|gist create\|edit`. No step may carry a redirect or `sudo`, and nothing outside the bodies may hold a pipe, substitution, subshell or background job. So a written file that is run, sourced, made executable, copied or piped on keeps every body line checked. `scriptdeny_diff_test.go` is the safety net: across a generated corpus it checks that everything the pre-rule decision denied is still denied, except a hand-reviewed list of intended passes and the relaxed shapes. `textTightened` lists the inputs the chmod and heredoc-pipe checks now deny. Unreadable files and `python -m` allow; `exclude_paths` skips trusted script dirs; `mode: soft` turns denials into warn events for pattern rollout. |
| `write-internal-names` | `write` | Deny Write/Edit content that mentions internal names when the target file is in a github.com repo. Names = `internal_names.blocked_words` (the section's own plus every included file's). Every git repo `kit/repofind` discovers under `internal_names.workspace_dirs` adds the org and repo segments of its origin remote (path fallback) and the checkout dir basename. Each is a separate name, never the combined `org/repo`. The set then drops `internal_names.allowlist` and anything under three characters. The same derivation the suspenders pre-commit guard uses, so the two layers agree when their configs do. `internal_names.allow_phrases` entries are neutralized in the content before matching, so a sanctioned compound carrying a blocked name passes while the bare name still denies. Public-bound is `config.PublicBound`: a match on the top-level `public_repos` list. Without that key, a rendering treats any github.com remote as public-bound (the legacy rule, kept so rollout skew tightens rather than disarms, docs/adr/0015). Non-repo paths are exempt. Per-guard `exclude_paths` skips paths that deliberately carry internal references (`~/` and absolute entries match as directory prefixes, others as substrings). Those live in the consuming repo's belt config overlay, not here (see docs/adr/0006). |
| `publish-internal-names` | `bash` + `external-text` | The outbound half of the internal-name firewall: the same `BlockedNames` set (and `allow_phrases`) matched against what leaves for a public github.com remote. One id registered twice in `All`, once per event. On `bash`: `git push` to a github.com remote scans the pushed ref names (explicit refspecs, the current branch or `@{push}` upstream for a bare push, every branch/tag for `--all`/`--tags`/`--mirror`; deletions skipped). The push also scans the messages of the outgoing commits (`git log -z` from the remote-tracking ref, else `refs/remotes/<remote>/HEAD`, else names only; capped at 200). The bash half also checks `git commit -m`/`-F`, `git tag`, and `checkout -b`/`switch -c`/`branch <name>`/`worktree add -b` in a github.com repo. The same goes for the writing gh subcommands (`ghPublishing`: pr, issue, release, repo, gist, label, every `gh api`) with the repo from `-R`, else the cwd origin, tracking `cd` like git-push-main. Commits, tags, and gh calls scan the whole command text (heredoc bodies span segments) plus the files they name (`--body-file`, `-F`, `--notes-file`, `--input`, `key=@path`, gist file args). On `external-text`: every MCP tool the matcher routes here whose operation is not a read verb (`internal/mcptool`), scanning every string in the input except top-level `owner`/`repo`. The target `github.com/<owner>/<repo>` goes through the same `config.PublicBound` + `allow_repos` test as the bash half. A call without one follows the mode (guarded under the legacy host rule, allowed once `public_repos` names the repos that matter) with a public-by-nature floor. That floor means gists, `gh api` on the gists endpoints, `gh repo create` without `--private`/`--internal`, and the MCP `create_gist`/`update_gist`/`create_repository` (unless `private`) calls, a prefixed operation such as `gh_com_create_gist` included, are guarded under both modes, whatever the cwd's origin. `gh api repos/{owner}/{repo}` endpoints and `gh repo create OWNER/REPO` resolve their own target the same way. `mode: soft` warns via events instead of denying. Empty name set fails open, like the write guard. |
| `rm-temp` | `bash` | Refuse a Bash call whose every `rm` deletes only temp paths, and hand over `toss-bin --temp-only` with the targets as written. A settings ask rule on `rm` shows a permission dialog for any rm, and a PreToolUse deny runs before that rule, so the agent reroutes and no dialog shows. toss-bin moves the paths to the trash, so the delete also stays recoverable. A target is temp when it cleans lexically (no stat, no symlinks followed) to a path strictly inside `/tmp`, `/var/tmp`, `/private/tmp`, `/private/var/tmp` or `~/.tmp`, the roots toss-bin accepts. A leading `~`, `$HOME` or `${HOME}` expands. A variable set from `mktemp` earlier in the same command counts too (`rmScan.assign`, plain, `export` or `local` assignments only). One made from a template or `-p` dir under a root is that path. One made in `$TMPDIR` is a fresh folder a target must stay in (`"$D"`, `"$D/sub"`), and the deny then adds that toss-bin refuses `$TMPDIR`, with the `mktemp -d /tmp/<name>.XXXXXX` form to use. Not temp: a root itself, a relative path, an unknown variable or substitution, brace expansion, a zsh glob qualifier, and a glob with a `..` component or a dot-led globbing component (`.*` matches `..` in bash before 5.2). rm counts only as a command name: after `!`, `{`, `if`/`then`/`do`-style words and `NAME=value` prefixes, and as `\rm` or `/bin/rm`. The command is read by the guard's own quote-aware reader (`rmtemp_lex.go`), which skips quoted strings, substitutions, comments and heredoc bodies; `splitSegments` splits inside quotes, which is why it is not reused. Every rm in the call must qualify, else no answer, since the dialog shows anyway. An option after an operand (BSD and GNU rm read it differently), an unknown option, and an rm with no operand also get no answer. Silent when `toss-bin` is not on PATH, which `belt doctor` marks on the guard's line. No mode and no repo lists. |

Adding a guard: implement the `Guard` interface in `internal/guard/`, register it in `All`, and add a toggle to the consuming repo's belt config overlay (`~/.config/belt/config.yaml`). Only a guard that needs a new tool matcher also needs a `hooks.PreToolUse` entry in the consuming repo's Claude settings recipe. A guard that must watch two events registers one instance per event under a single id (`publish-internal-names`); `ForEvent` keeps them apart and `GuardEnabled` switches both.

**Custom guards** skip the Go step entirely. A `custom_guards` entry in the belt config registers a named guard that execs an external command with the tool-call fields as JSON on stdin (`{"command","cwd"}` for bash, `{"file_path","content","cwd"}` for write). Exit 0 allows; exit 1 denies with stdout line one as the reason (prefixed `belt[<name>]:`). Exit 2+, a 5s timeout, or a start failure allow with a warn event, so a broken external fails open. An optional `match` substring gates when the external is exec'd at all, and `mode: soft` turns denials into warn events. Custom guards run after the built-ins, alphabetical by name; `belt doctor` lists them with a PATH reachability check. The commands run with the user's full environment on purpose — they are user-configured, not agent-configured, and belt never writes its own config.

### Allows

| id | event | rule |
|----|-------|------|
| `git-c-read` | `bash` | Off until `allows.git-c-read.enabled`. Runs only after `guard.RunClean` reports a clean pass. Answers only a call whose `tool_name` is exactly `Bash` and whose `tool_input` holds just `command`, `description`, `timeout`, and `dangerouslyDisableSandbox`/`run_in_background` when false (`plainBashInput`), when every command in it is `git -C <dir> <subcommand> [args]`, read by `plainSegments` (`plainshell.go`), a quote-aware reader that fails on anything beyond simple commands joined by `;`, `&&`, `\|\|` or newlines: pipes, redirects, `$`, backticks, `(`, `{`, `<`, `>`, `#`, `\`, globs, `^`, a word-leading `=`, a `~` the shell would expand anywhere but the dir, a quote inside a word-leading `~` prefix (zsh and bash disagree on `~'/x'`), and an empty command. `git` must be the unquoted first word (no env prefix, no wrapper), with exactly one `-C` right after it and the subcommand next. Subcommands (`gitReadForms`): status, log, diff, show, rev-parse, ls-files with any argument; branch only with listing flags (`--list`, `-a`, `--all`, `-r`, `--remotes`, `-v`, `-vv`, `--verbose`, `--show-current`) and a positional only beside `--list`; remote bare or `-v`; `worktree list` with `--porcelain`, `-v`, `-z`. `riskyGitArg` rejects anywhere: a long option that is any prefix of output, ext-diff, textconv, no-index, exec, upload-pack, receive-pack, open-files-in-pager, show-signature, help, exclude-from or resolve-git-dir (parse-options takes abbreviations); a short-flag word holding `O` or `X`; `%G` (signature placeholders run gpg); and a positional or `--option=value` value that is absolute, starts with `~` or has a `..` segment (implicit `diff --no-index`). The dir is joined to the payload cwd by concatenation and resolved with `filepath.EvalSymlinks`, never cleaned first, because git resolves `..` physically. `discoverRepo` (`gitrepo.go`) then finds the repo git would use without running git: no directory from the dir up to the top may look like a git directory (`HEAD` beside `objects`, `refs`, `commondir` or `config`); the first `.git` entry must be a real directory git accepts (`mainGitDir`) or a linked-worktree `.git` file whose gitdir is `<main>/.git/worktrees/<name>` with `commondir` and `gitdir` leading back (`linkedWorktree`); the work tree and every git directory must sit inside a root; `config`/`config.worktree` must set no `core.worktree`, true `core.bare`, `core.hooksPath`, `include` or `includeIf` (`configRisky`, which counts an unreadable line as risky); and belt's env must set no `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`. Roots: the work tree of the payload cwd unless it covers home, plus `allows.git-c-read.roots` (`config.Allow.RootDirs`: `~` expanded by concatenation, resolved physically; a relative, unresolvable, or home-covering entry is dropped with a doctor warning). |

Adding an allow: implement the `Allow` interface in `internal/guard/`, register it in `guard.Allows`, and document its `allows.<id>` key. It must stay off by default. Never give an allow a denial path, and never run it before the guards: the hook calls `guard.Approve` only after `guard.RunClean` returned a clean pass. A new guard that holds an `emit` func must implement `noteWarnings` (`clean.go`); `TestEveryEmittingGuardIsAWarner` enforces it.

Adding a hint: implement the `Hint` interface in `internal/hint/`, register it in `hint.All` (`ForEvent` filters that list by event), and add a `[hints.<id>]` toggle to the consuming repo's config overlay. A hint returns `*Advice` or nil: there is no way for it to deny. `Advice.Tags` labels the fire's events entry; `hook.adviceTags` keeps `hint`, `event` and the session identity tags out of a hint's reach. Tag names a consumer reads are listed in `docs/hooks.md` ("Tags on hint events").

**Custom hints** are the hint-side twin of custom guards. A `custom_hints` entry in the belt config registers a named hint that execs an external command. The command gets the hook payload fields as JSON on stdin (`{"event","cwd","session_id","transcript_path"}`, plus `agent_id`/`agent_type` inside a subagent). Its stdout becomes the advice, prefixed `belt[<name>]:`, with trailing whitespace trimmed and multiple lines kept. A non-zero exit, a run past the budget (400 ms by default, `timeout_ms` per hint), a start failure, or empty stdout is silence plus a warn event. A broken external therefore never breaks a session. `event` accepts `session-start` and `subagent-start` (`config.CustomHintEvents`). It stays a string so prompt and post-tool events can join without a schema break, and validation rejects anything else by name. Validation also rejects an empty `command` and a name that shadows a built-in hint. `config.HintFields` is the list it checks, and a hint package test pins that table to `hint.All`.

`enabled` and `exclude_repos` sit on a custom hint's entry, and a `hints.<name>` toggle of the same name is honored too. Custom hints run after the built-ins, alphabetical by name, through the same `belt hint session-start` and `belt hint subagent-start` entrypoints. No built-in hint runs on subagent-start: a subagent brief comes from the consuming repo's config. An optional `agent_types` list gates a subagent-start hint to the subagent types it names (`Custom.admitsAgent`, through `config.MatchAgentType`: exact, or by prefix for an entry ending in `*`). An unlisted spawn skips the exec and logs no warn event, since declining there is configured, not a failure. `CustomHint.UnmarshalYAML` records whether the key was written, so `agent_types:` with no value fails validation instead of reading as unset. `hook.hintAdviceByEvent` maps each start event to the hookEventName its envelope must carry (SessionStart, SubagentStart). `belt doctor` lists them with their budget and an executable check. The first consumer is a machine-private hint (a daily journal) that a private config overlay registers on one machine class. That is what keeps it out of this public repo.

### Ledger and watcher

`belt record <event>` (`internal/ledger`, `hook.RunRecord`) posts one events entry per lifecycle hook: subagent-start, subagent-stop, task-completed, teammate-idle, permission-denied, notification, pre-compact, post-compact, session-end, stop-failure (`ledger.Events`). Source `belt-ledger` (`ledger.source`), level info (stop-failure is warn for the transient error types in `ledger.transientErrors` and error for the rest), title with a qualifier, message capped at 500 bytes on a rune boundary, tags for every set field including `repo`/`worktree`/`canonical`/`branch` from `gitloc.LocationAt` (the shared `kit/gitloc` package). It takes no writer, recovers its own panics, and exits 0 for a valid event whatever happens: SubagentStop output keeps the subagent running, and TaskCompleted/TeammateIdle/PreCompact block on exit 2. A broken config records with the defaults and tags the entry. Never wire it on WorktreeCreate/WorktreeRemove: those hooks replace Claude Code's git worktree handling.

Two tags need care. `worktree` is the linked worktree's toplevel for the payload cwd, never the cwd itself, and on a spawn that cwd can be the parent's. A subagent-start entry whose `agent_type` matches a `ledger.agent_types` key also gets `model` and `effort` (`ledger.declaredTags`). The same `config.MatchAgentType` decides as for the hint gate: the exact key wins, then the longest key ending in `*`. A named spawn reports its name as its `agent_type`, which is why a key for named spawns ends in `*`. The map restates the agent definition; belt never infers a value.

`belt watch` (`internal/watch`, `hook.RunWatch`) is off until `watch.enabled`. As an asyncRewake hook on Stop and SessionStart it polls `GET /api/events?source=belt-inbox&q=<session>&since=<cursor>` and keeps entries whose `to` tag equals the session id. On a hit it moves the cursor (`~/.cache/belt/watch-<session>`), prints the items on stderr and returns `errWake`, which `cli.Execute` maps to exit 2. Newest watcher wins through `watch-<session>.pid`. A cursor that cannot be written means no delivery, because a delivery without one would wake the session on every Stop. Every other outcome is exit 0, silent.

## pi package

`pi/` is a pi package (`pi/package.json`, `pi.extensions: ./extensions/*.ts`) that pi loads in place from the ralph sources cache; the consuming repo declares it in pi's `settings.json`, the same way it declares `mods/`. The README's pi section covers what each extension does and the `belt.json` keys. Working rules:

- The gate stays fail-closed: a missing belt, a failed `belt check`, and an unreadable `belt.json` (a dangling symlink included) all block (reads excepted for the last). pi-mcp-adapter resolves tool names loosely: `server` is optional on the `mcp` proxy, an `mcp__<server>` namespace proxy takes the same `{ tool, args }`, and a name may carry a display or legacy server prefix. So the gate reads a call every way the adapter could run it, and each check takes the strictest reading. A proxy call it cannot place on a server still runs `belt check external-text`. The prefix and namespace forms are ported from the adapter's `types.ts`; keep them in step when the adapter changes them. The adapter's `mcpScript` makes its MCP calls inside the adapter, where no `tool_call` event fires, so every `mcpScript` call asks whatever the allow list says (headless with no broker, a block). The hints and the ledger records fail open. `belt:deny` (`{ kind, target, reason }`) is a contract with the session-band mod's pi face; keep the name and the three keys. Never announce a denial that is not belt's on it, since session-band counts every one as belt's. The ledger listens to `belt:permission-denied` (`{ source, reason, toolName, toolCallId }`) instead. The gate announces it through `announceDenial` for a belt guard, a settings deny rule, or the user. A broker decision counts as the user's only when its reason is `DENIED_BY_USER`, the broker's own constant.
- `belt-hooks.ts` maps pi events onto Claude Code hook payloads. The README's pi section has the table of which pi event records which ledger event. A record never waits. Its payload goes to a temp file that becomes the stdin of a detached, unref'd `belt record`, so a quitting pi can't cut it short. A spawn error, a missing belt included, is dropped. stop-failure records on `agent_settled`, not `agent_end`, because pi can retry a failed run after `agent_end`. The read hint sends pi's `read` as a Claude `Read`: an absolute `file_path`, `offset` and `limit` as given, and `tool_response: { type: "text", file: { totalLines } }`. On an unranged read `totalLines` comes from the result's truncation details. Otherwise the extension counts the file on disk the way pi does, splitting on `\n`. A `csl_read` goes to belt as-is, with its content blocks as the response. No hint runs for a call with a `parentToolCallId`, since a codemode script made it. stop-failure's `error` comes from `failureType`, a pure function with its own table test. It may return only types in the ledger's StopFailure vocabulary (`internal/ledger`), and `unknown` when the text is not clear.
- `belt.json` keys add to or override the defaults: the server lists only grow, and an `mcpPrefixes` entry can remap a default prefix. Unknown keys are ignored but named in the gate's config line, so a misspelt key shows up. The defaults name only this repo's servers and github.com. A machine's own server or sandbox variable belongs in the consuming repo's rendering of the file, never in `lib/config.ts`.
- `permission-broker.ts` keeps its env var names and `Symbol.for` keys. An extension outside this package may import its own copy, and the shared state on `globalThis` keeps a second load idempotent.
- Tests run with `make test-js` (`node --test pi/test/*.test.mjs`); `make test` runs them after the Go tests, and CI runs `make test-js` in the belt job. Each file runs in its own process because both extensions remember a missing belt for the process lifetime. For the same reason, pi picks up a belt installed mid-session only on its next start. For a load check without touching real pi state, run `pi -p --no-session --offline -e pi "hi"` with `PI_CODING_AGENT_DIR` pointed at a scratch dir. With no credentials there the run stops at "No API key found", and a load error prints before that line.
- pi loads nothing and prints nothing for a declared package path that does not exist. So the gate sets `globalThis[Symbol.for("mad01.pi.belt-gate")]` while it is live: at load and at session start, cleared at session shutdown. The consuming repo ships a small extension of its own that blocks every tool call while the marker is missing. Keep the key; it is that extension's contract. The consuming repo also checks the path itself (a ralph `[[tools]]` check), since pi never complains.

## Gotchas

- **The bash-command parser is token-based, not a shell parser.** It splits on `&&`/`||`/`;`/`|`/newlines and matches bare `git … push` sequences. Pushes buried in quoted strings or subshell tricks aren't caught; belt is a guardrail against habit, not an adversary-proof sandbox.
- **`publish-internal-names` scans whole command text on purpose.** A heredoc PR body spans several line segments. So a commit, tag, or gh call is checked against the entire bash command plus the files it names, not one flag value. A path elsewhere in the same command that carries an internal name therefore denies too. That is a true positive in a public repo, since the path is about to be public. Push checks shell out to git per pushed branch (remote URL, base ref, `git log -z`). So the guard costs one or two git calls only when a command actually pushes, commits, or calls gh in a github.com repo.
- **Same for `script-deny-list`.** `curl | bash`, list-form `subprocess.run`, quoted tokens, line continuations, and same-command write-then-run are covered now. But variable indirection (`k=kubectl; $k delete`), command substitution, shell function bodies, and a file an earlier command made executable, run later with no shebang, still slip through. An inline script still scans to the end of the command, so a text heredoc or an `echo "gcloud storage rm …"` after a `bash -c` or interpreter heredoc in the same command still matches. Flag reordering (`rm -r -f`) is an `extra_patterns` job — use a `re:` pattern rather than enumerating literal variants.
- **Runtime debugging lives in `operating.md`** (embedded in the binary, printed by `belt docs`): the no-daemon execution model and changes-apply-immediately behavior, the config fallback and fail-closed/fail-open matrix, deny false-positive paths, version-skew checks. Keep those facts there, not here.
- **`prefer-csl` does not reuse `guard.splitSegments`.** That splitter preserves byte offsets and treats `|` exactly like `&&`, which is right for finding a denied command anywhere in a pipeline and wrong for this hint. Telling a pipe filter apart from a standalone search is its entire precision requirement. The hint has its own quote-aware splitter so a `|` inside a grep pattern does not read as a pipe.
- **Version probe convention.** `belt version -o json` returns the shared four-key build metadata object (`version`, `commit`, `tag`, `build_time`, every key present and `""` when unknown) from `github.com/mad01/thismoon/buildinfo`, injected by `buildinfo.mk` at link time. Plain `belt version` stays a bare token — ralph and status parse it as one. `belt doctor` opens with the same metadata, so a doctor report always names the binary that produced it.
- **Keep literal internal hostnames and org names out of belt's own source and docs.** This repo is public and the suspenders pre-commit guard blocks them. Which repos are public-bound is enumerated in the rendered config's `public_repos` list (docs/adr/0015); the derived `github.com` rule is only the fallback for a config without the key. The list itself lives in the consuming repo, never here.
